## Core Content

Lesson 18 established the general default rule that the actual creator generally owns resulting intellectual property, absent a specific agreement. **Work for hire** is a specific legal concept and, in some jurisdictions, a specific statutory exception that changes this default in certain circumstances: [VERIFIED FACT] work created by an employee within the genuine scope of their employment is often automatically treated, by default, as owned by the employer, without needing a separate agreement — a meaningful exception to the general creator-ownership rule for this specific employment relationship.

Here's the "why" this exception matters especially for independent contractors, as opposed to employees, connecting directly back to Lesson 18: [VERIFIED FACT] the automatic employer-ownership rule for genuine employees generally does not extend automatically to independent contractors in the same way — for a contractor's work to be owned by the hiring business, many jurisdictions generally require an explicit, specific written agreement designating the work as "work for hire" (and, in some cases, this designation is itself limited to specific categories of work, depending on the applicable law), or otherwise explicitly assigning ownership to the hiring party.

This is why the specific status of the person creating intellectual property — genuine employee versus independent contractor, a distinction covered in more depth in this curriculum's employment law lessons — directly affects whether a written IP ownership agreement is legally essential, or whether the default employment-based rule already handles it.

## Worked Example

[ILLUSTRATIVE EXAMPLE] A software company's genuine, full-time employee writes code as part of her regular job responsibilities. Under the work-for-hire concept, this code is generally automatically owned by the employer, without needing a separate written IP agreement specifically addressing this work. [ASSUMPTION] If the same company instead hires an independent contractor to write similar code, the automatic employer-ownership rule generally doesn't apply in the same way — the company needs a specific written agreement explicitly addressing work-for-hire status or assigning ownership, or it risks not actually owning the code it paid the contractor to create, echoing directly the default rule and risk described in Lesson 18.

## Key Takeaways
- Work for hire generally reverses the default IP ownership rule for genuine employees, automatically vesting ownership in the employer.
- This automatic rule generally doesn't extend to independent contractors in the same way.
- A specific written agreement is essential when hiring contractors to create intellectual property the business intends to own.
